AGENT RSI · ROBO RSI · FRAMEWORK

Agent RSI 与 Robo RSI：持续自我改进的闭环

框架稿：将此前 Agent RSI 与具身 RSI 的讨论放在同一套三级 taxonomy 下。这里的 RSI 是能够通过经验与验证形成持久改进的系统闭环，不要求每次都改模型权重；下面是分析框架，不是已有系统的效果声明。

先回答「谁在什么时候做什么」：任务执行者在环境中运行并产生轨迹；改进器在步骤失败、任务结束或定期检查点读取经验、诊断瓶颈并提出修改；Verifier 在独立任务和旧能力集合上验证修改；部署者只将通过门槛的版本持久化，交给下一轮执行者使用。改进器、Verifier 和执行者可以由同一个 Agent 承担，也可以由模型、Harness 与外部评测器分工。一次反思或单次重试不是持续自我改进；关键是修改能否跨任务保留、再次被检验。

共同框架：总问题 → 六个维度 → 具体类别

一级问题是「系统如何从经验中持续改变自身，并证明改变带来能力增长？」下表六个维度是二级；每行的三类是三级。它们是用于定位工作的观察轴，不是要求一项工作同时覆盖所有类别。

二级维度三级类别与要问的问题
WHAT · 改进什么Model / Policy：基础模型、VLM / LLM、VLA / Action Policy 或辅助模型；
Harness / Scaffold：Context、Prompt、Memory、Tool、Skill、Workflow 与 Harness Code 的组成和组织；
Meta-Optimizer：改进模型或 Harness 的优化器，乃至优化过程本身。尤其要检查 Harness 内部有哪些可替换组件、如何连接，不只把它记作「非参数」。
WHEN · 何时改进Intra-Task：步骤级适应、失败触发的重试／反思、测试时学习；
Inter-Task：一轮任务到下一轮、批量／周期更新、版本间更新；
Continual：在线、周期或长期持续演进。区分「本次任务内恢复」与「下一轮持久能力变化」。
HOW · 如何改进Experience Generation：成功轨迹、失败／探索轨迹、示教或合成经验；
Evaluation & Diagnosis：成功／奖励信号、Executable Verifier / Critic / 偏好、失败根因与责任归因；
Update Mechanism：参数化 SFT / RL / 偏好学习，非参数 Memory / Prompt / Skill / Code 修改，或搜索／进化筛选。
WHERE · 在哪里发生Offline / Dataset：现成数据和离线评测；
Interactive Environment：仿真、软件环境或真机中的交互 Rollout；
External Interaction：外部工具、人类监督或其他 Agent 参与。环境决定反馈是否可执行、采集成本和风险边界。
CAPABILITY · 得到什么Refinement：已有弱能力从偶尔成功变得更稳定；
Adaptation：针对新场景／条件迁移已有能力；
Acquisition：原本不会的任务获得新能力。最关键的试验是 zero-success / failed rollout 能否提供有效信号，让成功率从零附近变为非零，而不只挑出已有的成功样本。
GOVERNANCE · 如何约束Persistence / Continuality：变更能否跨轮次保留、审计和回滚；
Regression / Safety：旧能力不回退、真实环境安全与 Verifier 防误判；
Efficiency / Autonomy：数据、算力、真机时间的消耗，以及人类介入和自主改进的界线。

Agent RSI：改进对象不限于模型

在软件 Agent 中，任务、工具调用和执行 Trace 往往可以回放，因此 Prompt / Memory、可执行 Skill / Code、工具协议、任务工作流和 Verifier 都可能成为更新对象。Voyager 的可执行 Skill Library 是其中一种公开例子。要分别记录执行者改了什么、改进器是否还能改进自己的选择／验证机制，以及提案是否通过独立测试。单纯更换基础模型不等于 Agent 自我改进；只有系统根据自身经验产生、验证并持久化变化，才能讨论它的持续性。

Robo RSI：同一框架在物理环境中的特化

具身 Agent 的执行者可以是 System 2 Planner / Harness 与 System 1 Policy / Skill 的组合。WHAT 要分清是训练了底层 VLA Policy，还是修改上层 Planner、Memory、调度和恢复机制；其中 Skill / Code 是一条值得单独观察的非参数路径（可参看RoboRSI 项目）。HOW 的经验既有成功示教，也有自主 Rollout 的失败、状态变化和安全事件；WHERE 则要区别离线、仿真和真机，不能把模拟验证直接视为真机有效。

一个 Robo RSI 的可检验例子是：失败 → 根因诊断 → 定位受影响的 Skill / Code → 提出局部修订 → 仿真 Replay 与旧技能 no-regression gate → 持久化新版本 → 真机复核。另一条路径是用 Rollout 更新 VLA 参数。两条路径可以并行，但改善的是不同层级的能力，不能因为成功率变化就笼统称作「机器人会自我改进」。若初始任务几乎没有成功，特别要说明系统是从失败信号、探索或额外监督中习得新能力，还是仅仅对已经能做的任务进行 refinement。

验证边界与后续补充

Executable Verifier 应尽量给出可复现的任务结果、Trace / Replay、成功与失败判定；晋级同时检查目标能力收益、旧能力回归、安全、资源成本与持久性。把「训练方法 SFT 还是 RL」作为 HOW 的一小部分即可，能力获得、更新对象和反馈来源通常更能解释一项工作是否真的形成 RSI。后续再把代表性 Agent RSI / 具身 RSI 工作映射到六轴；当前先固定框架，不堆论文。

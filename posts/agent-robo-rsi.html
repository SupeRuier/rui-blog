AGENT RSI · ROBO RSI · FRAMEWORK

Agent RSI 与 Robo RSI：持续自我改进的闭环

框架稿：这是一套分析 Agent / Robo 持续自我改进的两级 taxonomy，不是已有系统的效果声明；改进对象可以是模型，也可以是 Harness、Skill 或 Code。

系统如何从经验中持续改变自身，并证明改变带来能力增长？

执行者在环境中产生轨迹，改进器读取经验并提出更新，Verifier 对新旧能力进行独立验证，合格的变更才被持久化并用于下一轮。一次反思或本轮任务的临时重试，不等于跨任务的持续自我改进。下面六个一级维度分别回答不同问题；每张小图里的三个节点是该维度的二级类别。它们是观察轴，不必在每项工作中全部出现，也不都互斥。

01 · WHAT：改进什么

模型侧可更新 LLM / VLM、VLA / Action Policy 或辅助模型；系统侧可更新 Prompt、Memory、Tool、Skill、Workflow 和 Harness Code。尤其不能只把 Harness 记作「非参数」：要看内部有哪些可替换组件、如何组织、谁来验证修改。第三类 Meta-Optimizer 指改进器本身的选择、搜索或验证机制是否也被更新；这比单纯修改执行者更进一步。

02 · WHEN：何时改进

任务内适应可以是失败触发的重试、反思或测试时学习；任务间更新可以基于一次任务或批量经验形成新版本；长期改进则需要重复采集、更新、验证和部署。这里Continual 不是与前两者互斥的触发时刻，而是多个更新周期串起来后的持续性。分析时一定区分「本轮恢复成功」与「下一轮保留了新能力」。

03 · HOW：如何从经验形成更新

先问经验从哪里来：成功轨迹、失败与探索 Rollout、人工示教还是合成样本。再问谁判断结果与根因：奖励、Critic、可执行 Verifier、偏好或人类反馈；没有可靠的失败归因，后续更新可能只是在优化错误目标。最后问更新机制：SFT / RL / 偏好学习修改权重，Memory / Prompt / Skill / Code 修改系统结构，也可以搜索候选并用验证器筛选。这三项是同一链路中的环节，不是必须三选一的算法家族。

04 · WHERE：经验与验证在哪里发生

离线数据利于复现，但不一定覆盖当前策略的失败分布；交互式 Rollout 能观察行动的真实后果，却涉及算力、真机时间与安全边界；外部工具、人类或其他 Agent 可以提供额外监督。External 可以与 Offline 或 Interactive 并存，不是独立部署地点。尤其 Robo RSI 要把仿真有效与真机有效分开报告。

05 · CAPABILITY：究竟获得了什么能力

已有任务偶尔成功后变得稳定是 refinement；同一能力迁移到新场景或新本体是 adaptation；起初近乎 zero-success 的任务通过失败、探索或额外监督出现可验证成功，才更接近 acquisition。是否能从 zero-success / failed rollout 中获得有效信号，是比单纯比较 SFT 与 RL 更有解释力的轴。只训练成功样本，不能直接声称系统习得了原本不会的新技能。

06 · GOVERNANCE：如何约束改进

一个提案只有进入可复现的版本管理、经独立任务与旧能力集合验证、能在失败时回滚，才是持久改进。晋级同时报告目标能力收益、旧能力回退、Verifier 误判、算力和交互成本；真机系统还需要独立的安全门槛。人类是否必须批准、系统是否能自行生成并筛选更新，也要作为自治程度记录。

同一框架，Agent 与 Robo 的着力点不同

软件 Agent 的 Trace、工具调用与可执行代码通常更容易回放，Prompt / Memory 与 Skill / Code 都能成为 WHAT 的更新对象。Voyager 的可执行 Skill Library 是一条公开的非参数化路线[1]。具身系统的执行者则可能由 System 2 Planner / Harness 与 System 1 Policy / Skill 共同构成：须区分底层 VLA 的参数更新和上层调度、记忆、恢复或 Skill / Code 的变化，相关 Harness 路线可参看RoboRSI 项目[2]。两类系统可以共用分类轴，但真机反馈成本、物理安全与仿真到真机的验证边界不同。

例如 Robo RSI 的一个待检验工程路线是：失败 → 根因诊断 → 局部修订 Skill / Code → 仿真 Replay 与 no-regression gate → 持久化版本 → 真机复核。另一条路线用 Rollout 更新 VLA 参数。两条路线改进的是不同层级；不能只因为某次成功率提高，就笼统宣称机器人会自我改进。后续可把代表性工作映射到六轴，目前先明确框架与可验证的能力边界。

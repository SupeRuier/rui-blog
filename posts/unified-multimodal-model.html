统一多模态模型架构（UMM）：理解与生成如何共用底座

框架草稿。UMM 在本文指统一多模态理解与生成的模型目标；这是曾经设定、但尚未跑通完整训练与验证的方向，不是已完成的模型或公开训练成果。

通用 VLM 更多处理「看见内容，输出语言」；统一多模态模型希望进一步处理图文交错输入、文本推理和图像／视频生成，让不同模态既能作为条件，也能成为输出。这里的「统一」不要求所有输入共用同一个编码器，而是要求清楚定义跨模态表示、共享主干、输出路径和训练目标。

架构主线

一个简洁的抽象是：文本与视觉先经各自的 tokenizer / encoder 进入模型，组成带有模态边界和时序信息的序列；共享 Transformer 建模跨模态上下文；语言输出、视觉 token 解码或专门的生成头负责不同输出。视觉表示存在取舍：离散 visual tokens 方便把理解与生成放进自回归序列，连续视觉特征有利于保留感知语义；理解与生成对视觉细节的要求也不一样，因此可以共享主干但拆开编码／解码路径。Emu3[1] 与 Janus[2] 展示了两种可对照的设计，而不是唯一方案。

数据与训练，比单一结构更关键

训练样本需要覆盖纯文本、图文交错、视觉理解和视觉生成，并明确每种任务的输入、输出、模态边界、损失及采样比例。高质量的图文对齐与 interleaved 数据不足时，单纯把多种任务混进一次训练未必能够收敛，也可能让语言、感知或生成能力互相牵制。更稳妥的研究路线是依托已有 LLM / VLM 能力，先验证模态接入与单任务效果，再逐步混合任务、监测能力回退；数据版本、质量过滤、配比实验和误差切片应与结构选择一起设计。这一问题与通用世界／具身理解 VLM 的训练、数据与评估相连，但前者讨论理解／生成共用底座，后者讨论世界与具身理解能力的建设和验证。

能力边界与验证

评价不能只看图像生成质量，也要分别检查文本能力、视觉问答／grounding、图文交错理解、生成，以及跨模态多轮任务是否保持一致。机器人动作可以作为未来输出模态之一，但离散 Action Token 的序列预测与连续 Action Policy / 轨迹控制有不同的精度和延迟约束；把动作 token 拼进序列并不自动等于可部署的 VLA，也不意味着模型已经具备环境预测能力。这里暂不把 World Model、未来状态预测或视频生成机器人策略混作同一个架构目标。

后续可沿「表示接口 — 训练数据 — 验证指标」补充实验与公开系统对比；在没有完成训练前，保持目标、方法与成果三者分离。

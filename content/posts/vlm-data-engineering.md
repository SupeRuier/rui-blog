::: tldr
「让模型理解世界」这句话无法直接执行。要做成可训练、可验证的东西，必须先回答三个递进的问题：**能力怎么定义 → 任务怎么构造 → 数据怎么覆盖**，最后才是训练路线和阶段划分。

本文按这条链条组织。核心立场是：**能力清单必须先于数据集存在**。每条能力都要能写出输入形式、输出形式和判通道具；写不出判分接口的能力，实际上还没有被定义，而只能在一个特定数据集上得到一个分数。

**「任务链路打通」与「模型训练完成」是两个验证层级**。前者要求数据 schema、任务构造、判分接口、训练与评估流程能够端到端运行并产出可复现数字；后者要求模型在目标能力清单上达到预先定义的门槛，并通过对照与泛化验证。

评测协议、统一框架与服务侧细节由《具身系统评测：从模型能力到部署现场》的模型／能力评测一章展开。
:::

::: question
如何把场景、空间、因果这些抽象能力，拆成可构建数据、可训练、可验证的任务？
:::

这类模型既要保留图像、视频和语言的通用理解能力，也要理解场景中的物体、空间关系、时序变化、交互可能性与任务语境。目标不是只做好单项机器人 benchmark，而是让一个可复用的视觉语言底座支撑感知、推理、Grounding 和高层任务判断。

## 能力清单：先写判分接口，再找数据

抽象能力要落成可判分的任务，第一步是把能力清单写细到「可判分」的程度。对世界理解来说，至少要覆盖四组：

- **空间**：相对位置、遮挡关系、可达性、尺度与距离比较；
- **时序**：动作顺序、状态变化、事件之间的先后与因果；
- **交互可能性**：可供性、可操作性、物体与动作的匹配；
- **任务语境**：给定目标时哪些对象与约束是相关的。

每条能力都要能写出三件事：**输入是什么、输出以什么形式表达、怎样算通过**。这三件事写不出来，说明这条能力还没有被定义清楚，此时去找数据只会得到一个「能训但不知道在训什么」的结果。

> **一个常见的方法论反转：先有数据集，再从数据集反推能力清单。** 这样做出来的能力清单必然与那个数据集的标注体系同构，「能力」就退化成了「这个数据集上的分数」。更稳的顺序是先写能力与判分接口，再去找或造数据；找不到合适数据是一个有用的信号，说明这条能力暂时无法验证。

## 训练：先定义能力，再设计阶段

从已有语言与视觉能力出发，规划模态对齐、跨域持续训练与具身任务适配，分别观察每一阶段获得的能力和旧能力是否回退。训练目标可以覆盖视觉问答、空间与时序推理、目标定位、可交互性判断及因果链条表达；图像和视频的采样方式、长上下文成本、数据混合比例与损失配置应与目标能力一起讨论。训练路线是否有效，必须由各阶段的对照评估回答，不能仅凭训练 loss 下降认定具身理解增强（参考 [RoboBrain 2.0](https://arxiv.org/abs/2507.02029)[@1] 的分阶段训练）。

第一阶段 GRPO 按输出结构选择奖励：框用 IoU、点用距离、轨迹用 Fréchet distance，离散答案用 exact match，无法规则判定时才使用 LLM Judge。通过筛选的 rollout 形成约 100 万条长 CoT；RFT 从 θpt 重启而不是沿用 θRL，最后再训练连续／离散奖励专家并融合[@6]。

分阶段训练有两个必须显式设计的东西：**每阶段的判据**，以及**回退检查**。前者防止「这一阶段到底学会了什么」变成一句无法验证的描述；后者针对的是灾难性遗忘——具身适配阶段把通用视觉语言能力压低，是这条路线最常见的代价，而它只会在跨阶段对照里暴露。

数据混合比例不是调参细节，而是一个与能力目标绑定的设计量：把具身数据比例拉高会提升具身切片，同时压低通用能力，这个交换必须被报告，而不是只在提升的那一侧报数字。

## 数据：从资产转换走向能力覆盖

文本、图像、视频、场景标注及任务轨迹等多源资产，需要经统一 Schema、质量过滤、去重、样本构造和版本管理转成可训练输入。通用数据保证语言和视觉基本盘，真实世界与具身数据补足空间、时序、视角变化、动作语义和复杂交互；不同来源的数据质量、监督密度和成本各不相同。除数据量外，还要审视长尾场景与任务切片覆盖，围绕因果链条组织 CoC 类样本，并让训练反馈反过来调整数据选择和混合比例。

### 两条加工链：先能稳定读取，再有任务语义

**格式标准化**解决「同一训练器能否可靠读取」：先识别每个来源的字段、媒体引用和样本粒度，把它们映射到固定版本的中间 Schema；转换后检查必填字段、媒体可读取性、样本数与去重结果。失败样本记录原因，修复映射后重跑校验；自动修复需要有限重试，无法收敛时交给人工，而不能让错误数据悄悄进入训练。来源、转换版本和校验结果应随样本保留，以便训练异常时回查。Parquet 可以承载统一中间表，但文件格式本身不保证语义一致。

**任务语义构造**解决「样本究竟教会模型什么」：以驾驶片段中的因果问答为例，先对齐视频、轨迹和动作，再分开确定三层信息——真正约束当前行为的场景要素、与行为真值一致的决策、以及「约束如何影响自车，因而触发什么动作」的文字解释。遇到车辆切入，不应罗列画面中的所有车；需要指出切入目标、它怎样改变通行空间或安全距离，以及对应的减速或横向调整。每层分别核查事实、时序和决策一致性，避免一段流畅的回答掩盖不存在的要素或事后编造的因果关系。

这两条链的产物也不同：前者是**可追溯、可重跑的标准样本**，后者是**针对某项能力设计的监督信号**。统一格式是任务构造的基础，却不能代替任务定义；因果文字看起来合理，也不能代替与视频和动作真值的独立核对。

## 覆盖度检查：按能力切片，而不是按总量

数据规模是最容易被拿来汇报的数字，也是最容易掩盖问题的一个。可用的做法是维护一张**能力 × 数据来源**的覆盖表：

| 检查项 | 要回答的问题 |
| --- | --- |
| 能力覆盖 | 能力清单上的每一条，分别由哪些数据来源支撑？有没有能力完全没有对应数据？ |
| 难度切片 | 同一能力在简单／中等／困难切片上的样本量分别是多少？ |
| 来源可信度 | 真实观测、生成补全、人工构造各占多少？（来源分层原则见数据体系一文[@4]） |
| 监督密度 | 同一批样本上是有标注、弱标注，还是仅靠自监督？ |
| 长尾与风格 | 视角、光照、地域、本体类型的分布是否被少数几类主导？ |

这张表的价值在于把「数据够不够」从一个总量问题变成一个**逐能力可核对**的问题。缺哪一格，通常就直接对应到评估结果里哪一类能力最弱——两者对不上时，说明评估维度或数据分类有一方是错的。

## 评估：通用能力与具身能力分层看

基础层看语言、图像理解、视频理解和视觉 Grounding；世界／具身层看空间关系、时序变化、可交互性和高层任务理解；系统层再看模型接入 Robot Agent 后的端到端任务成绩、延迟与稳定性。基准结果之外，还需用目标任务切片、跨场景／跨本体泛化、误差案例与训练前后对照识别能力提升或回退（参看[STI-Bench](https://arxiv.org/abs/2503.23765)[@2] 的评测维度）。离线问答成绩不能直接代替真实任务收益，模型选型与模型训练也应分别验证。

## 验证层级：任务链路打通 ≠ 模型训练完成

两者的验证对象不同。

**「任务链路打通」指的是基础设施可用**：能力清单与判分接口定义完成、数据 Schema 与版本管理建立、任务构造脚本可以批量生成实例、训练与评估流程能端到端跑通、并且能产出可复现的数字。它证明的是**这套方法可以工作**。

**「模型训练完成」指的是能力结论**：在目标能力清单上达到预先定义的门槛，并且有对照实验（相对基线、相对上一阶段）、跨场景或跨本体泛化验证、以及误差案例分析支撑。它证明的是**模型确实具备了这项能力**。

链路跑通只说明流程能产出数字，不说明数字达到能力门槛；数字好还需要排除数据泄漏、判分器偏差、任务过于简单等解释。因此，链路可用不能直接推出模型能力达标。

顺便明确与相邻方向的边界：理解模型的输出是文本或结构化描述，VLA 类模型的输出空间是动作 token[@3]，两者的训练数据、判分方式与评测目标都不同。世界理解不包含动作控制，也不包含未来状态生成。

这里的「世界理解」强调对观测到的环境及交互的语义、空间和时间理解；未来状态生成与动作控制属于相关但不同的目标。公开参考：[RoboBrain 2.0](https://arxiv.org/abs/2507.02029)[@1] 对具身 VLM 能力与训练的划分、[STI-Bench](https://arxiv.org/abs/2503.23765)[@2] 对空间／时序理解的评估问题。

## 与评测文章的分工

本文回答的是**能力怎么定义、数据怎么建、训练怎么分阶段验证**；评测协议的设计、判分接口与判分器本身的可靠性、统一评测框架、以及结果的分层报告，属于 [具身系统评测：从模型能力到部署现场](robot-agent-evaluation.html) 的模型／能力评测一章。本文中的「评估」一节只到「该看哪些层」为止，不再往评测实现下沉。

::: my-take
我认为这个方向最容易犯的错误是**用数据集的边界代替能力的边界**。一条能力如果只能在一个数据集上被验证，它就不是能力，而是一个 benchmark 分数。因此能力清单必须先于数据集存在，并且每条能力都要能写出判分接口——写不出判分接口的能力，实际上还没有被定义。

这也解释了为什么「覆盖度」应该按能力切片而不是按总量统计：总量达标从来不保证能力齐全。
:::

::: my-take
「任务链路打通」与「模型训练完成」具有不同的**可证伪方式**：链路用「能否复现出数字」验证，能力则用对照与泛化验证。前者证明基础设施可用，后者才形成能力结论；不能用「流程能跑」替代「能力达标」。
:::

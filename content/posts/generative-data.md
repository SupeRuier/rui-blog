::: tldr
补充天气、昼夜、风格或稀缺目标数据时，真正要先回答的不是「用哪个生成模型」，而是**这批数据的缺口属于哪一类**：是同一场景缺条件覆盖，还是某个类别本身缺实例。

本文把可控数据生成分成两条路径，判据只有一条——**目标类别的真实样本是否足以训练**：

- **够** → 走**条件生成**：改的是条件，保留原图标签；
- **不够** → 走**参考图插入**：改的是实例，标签由放置参数直接生成。

两条路径放同一篇，因为它们共享同一个下游要求：**标签必须与渲染真正对齐**。参考图插入不另开文章。

如果只记一句：判断走哪条路的标准不是技术难度，而是**标签从哪里来**——条件生成继承标签，插入路径生成标签，两者都必须证明标签与实际渲染出的像素一致。
:::

::: question
当需要补充天气、昼夜、风格或稀缺目标数据时，如何选择生成路径，并保证产物真的能用于下游任务？
:::

生成式数据增强的目标，是以可控方式补充真实数据中稀缺、昂贵或组合空间过大的样本。生成质量只是第一步，条件可控性、场景一致性和下游有效性同样重要。当前具身与驾驶模型的规模增长已经把数据量推到主要瓶颈的位置——百万小时级的 scaling law 正是这一判断的体现[@6]——但**「更多数据」和「更对的数据」是两件事**，本文只处理后者。

## 主要任务

- 框选、Mask、文本和参考图条件生成
- 对象插入、移除与局部场景编辑
- 稀有目标、复杂布局和长尾组合生成
- [Diffusion](https://arxiv.org/abs/2006.11239)[@1] 与 [Flow Matching](https://arxiv.org/abs/2210.02747)[@2] 的生成路径设计

## 先分清是哪一类数据缺口

「数据不够」有三种互不相同的形态，补法也不同：

| 缺口类型 | 表现 | 主要补法 |
| --- | --- | --- |
| 条件覆盖缺口 | 同一场景缺雨天 / 夜间 / 特定光照 | 条件生成 |
| 类别长尾缺口 | 某类目标本身样本就少 | 参考图插入（实例来自真实图像） |
| 组合缺口 | 单类都够，特定相对位置、遮挡、光照组合少见 | 两者都可能，取决于组合里的稀缺项是条件还是实例 |

分不清缺口类型，就会用错工具：拿生成模型去补一个本来已经有充足真实样本的类别，通常不是增加覆盖，而是**把分布往生成模型的偏好上拉**。

## 条件数据 Schema：把「想要什么」写成可执行的条件

条件必须是机器可执行的，不能是一句自然语言描述。一个够用的条件 schema 至少包含四组字段：

- **生成条件**：天气、时段、光照强度与方向、风格；
- **空间条件**：目标类别、位置（BBox / 掩码 / 深度平面）、尺度、朝向、遮挡关系；
- **场景约束**：不可改变的区域（保留掩码）、相机参数、地平线与消失点；
- **输出约定**：分辨率、颜色空间、是否需要同步输出深度或语义标签。

Schema 写不出来，说明这批数据的需求还没定义清楚。它同时是质检依据——生成完成后要逐条核对条件是否真的被满足，而不是看整体观感。

## 路径 A：条件生成

适用场景是「目标本身不缺样本，缺的是它在不同条件下的样子」。

Diffusion 与 Flow Matching 是两条主干，差别在于建模对象（离散去噪过程 vs 连续流）以及采样步数与训练稳定性的取舍[@1][@2]。对数据生产而言，比骨干选择更关键的是**条件注入方式**与**能否批量稳定产出**——单张样例好看没有意义，需要的是同一条件下成百上千张都不崩。

条件生成的三种典型失败：

1. **条件不生效**：生成的「雨天」只是整体加噪，没有改变光照、路面反射与可见度；
2. **条件生效但破坏场景**：背景漂移、结构变形，插入的样本在几何上不再对应原场景；
3. **多样性塌缩**：同一条件反复产出高度相似的样本，增加的是数量而不是覆盖。

因此条件生成要报告的不是「生成了多少张」，而是**条件满足率**与**条件内多样性**。

## 路径 B：参考图插入

适用场景是「某个实例本身稀缺而真实」——比如罕见车型、特殊外观设备——需要在指定位置、指定尺度上出现。

本质上是把**实例的真实外观**与**场景的几何与光照**重新组合，可以分两个层次做：

- **二维合成**：按掩码把实例贴到目标位置，再做光照与阴影调和。成本低，但新视角一致性无从谈起；
- **三维/显式表示**：在可编辑的场景表示中放置资产并重新渲染。3DGS 的显式高斯表示便于这类编辑[@3]，Street Gaussians 的背景—车辆分层更是直接为此设计[@4]。新视角一致性与遮挡关系更可控，代价是依赖场景重建质量。

**插入路径最大的价值是标签免费而且精确**：目标的位置与 BBox 由放置参数直接给出，不需要事后标注。但由此带来两条必须显式约定的事：

1. **标签要覆盖实际渲染出来的像素范围**，包括边缘的抗锯齿过渡带；阴影不应计入 BBox，否则框会随光照变化；
2. **遮挡要有明确口径**：实例被场景物体挡住时，是标记 truncated / occluded，还是直接丢弃这条样本，必须在 schema 里定死。

## 标签与质检

插入路径的标签「免费」，但不等于「正确」。可用的质检清单：

- **条件满足率**：逐条核对生成条件是否被满足；
- **几何与语义一致性**：目标与地面的接触点、尺度是否符合透视，遮挡是否正确；
- **伪影检查**：边缘光晕、复制粘贴痕迹、不自然的重复纹理；
- **标签对齐**：把标签可视化叠加回图像，逐张确认边界；
- **与真实分布的差距**：用真实集上的统计量（目标尺寸分布、位置分布、出现频次）对照，避免生成数据把分布推向某个窄区间。

每条样本都要带来源标记：**真实 / 条件生成 / 插入**。三类混在一起报指标，下游就无法判断收益来自哪里。

## 训练闭环：生成数据怎么进入训练

生成数据的最终判据是下游收益，而且必须分开报告：

1. **真实测试集上的收益**——唯一能说明问题的指标；
2. **长尾子集上的收益**——生成数据最应该改善的地方，若这里没有改善，说明补错了地方；
3. **常见类别是否变差**——生成样本挤占真实分布时的典型症状。

闭环本身要控制变量：同样的真实数据量、同样的训练预算、同样的超参，只改生成数据的混入比例。否则「提升」可能只是训练得更久或见得更多。混入比例本身也是一个需要报告的超参——生成数据占比过高会让模型学到渲染伪影。数据配方里应当把生成样本的来源类别与混入比例一并记下[@5]，这样下游复查时才能区分「换了数据」和「换了配方」。

## 如何评价

数据增强不能只依赖视觉观感。需要同时检查几何和语义一致性、生成多样性、标签可用性，以及加入训练后对真实测试集和长尾场景的实际收益。

::: my-take
我认为两条路径的划分依据不是技术难度，而是**标签从哪里来**。条件生成改的是条件、继承原有标签；参考图插入改的是实例、由放置参数生成标签。两者都要回答同一个问题：标签是否与真正渲染出来的像素一致。这个问题答不上来，数据量再大也不构成训练资源。

选择路径的可操作标准只有一条——**目标类别的真实样本是否足以训练**。够，就去改条件；不够，就去插入实例。用生成模型去补一个本来就有充足真实样本的类别，得到的通常不是覆盖，而是偏差。
:::

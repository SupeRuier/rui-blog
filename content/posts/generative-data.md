::: note
本文关注生成模型如何服务数据生产：先识别数据缺口，再选择控制条件与标签策略，最后通过真实测试集验证价值。图像与结果用于说明这些环节各自能证明什么。
:::

::: tldr
补充天气、昼夜、空间排布或稀缺目标数据时，真正要先回答的不是「用哪个生成模型」，而是**缺的是什么**：外观条件、目标之间的组合，还是目标实例本身。

本文把生成路径分成两类：

- **条件控制生成**：用天气、光照、边界框或布局约束改变已有场景。条件类型不同，原标签能否沿用也不同；
- **参考图插入**：用真实参考实例补足类别长尾，控制它在场景中的位置、尺度与接地关系。

两条路径放同一篇，因为它们共享同一个下游要求：**生成目标、标签和渲染像素必须对齐**。参考图插入不另开文章。

如果只记一句：生成条件可以提供初始标注依据，却不能自动保证样本可用；最后必须由质检和真实测试集回答它是否有效。
:::

::: question
当需要补充天气、昼夜、风格或稀缺目标数据时，如何选择生成路径，并保证产物真的能用于下游任务？
:::

生成式数据增强的目标，是以可控方式补充真实数据中稀缺、昂贵或组合空间过大的样本。生成质量只是第一步，条件可控性、场景一致性和下游有效性同样重要。当前具身与驾驶模型的规模增长已经把数据量推到主要瓶颈的位置——百万小时级的 scaling law 正是这一判断的体现[@6]——但**「更多数据」和「更对的数据」是两件事**，本文只处理后者。

## 主要任务

- 框选、Mask、文本和参考图条件生成
- 对象插入、移除与局部场景编辑
- 稀有目标、复杂布局和长尾组合生成
- [Diffusion](https://arxiv.org/abs/2006.11239)[@1] 与 [Flow Matching](https://arxiv.org/abs/2210.02747)[@2] 的生成路径设计

## 先分清是哪一类数据缺口

「数据不够」有三种互不相同的形态，补法也不同：

| 缺口类型 | 表现 | 主要补法 |
| --- | --- | --- |
| 条件覆盖缺口 | 同一场景缺雨天 / 夜间 / 特定光照 | 条件生成 |
| 类别长尾缺口 | 某类目标本身样本就少 | 参考图插入（实例来自真实图像） |
| 空间与组合缺口 | 单类样本足够，但特定排布、遮挡或相对位置少见 | 用边界框等结构条件控制布局，再核对目标与标签 |

分不清缺口类型，就会用错工具：拿生成模型去补一个本来已经有充足真实样本的类别，通常不是增加覆盖，而是**把分布往生成模型的偏好上拉**。

生成还应放在更大的数据选择顺序里：先查存量真实数据是否已有目标场景；若要保留某段真实街景的几何与外观，只改变局部目标或标识，可考虑[可编辑场景重建](3dgs-scene-reconstruction.html)；存量与可编辑资产都覆盖不了，或需要跨许多背景扩展目标组合时，再进入本文的生成路径。这是按**覆盖需求、真实性、可控性和单位有效样本成本**选工具，不是给三种技术排先进程度。

## 条件数据 Schema：把「想要什么」写成可执行的条件

条件必须是机器可执行的，不能是一句自然语言描述。一个够用的条件 schema 至少包含四组字段：

- **生成条件**：天气、时段、光照强度与方向、风格；
- **空间条件**：目标类别、位置（BBox / 掩码 / 深度平面）、尺度、朝向、遮挡关系；
- **场景约束**：不可改变的区域（保留掩码）、相机参数、地平线与消失点；
- **输出约定**：分辨率、颜色空间、是否需要同步输出深度或语义标签。

Schema 写不出来，说明这批数据的需求还没定义清楚。它同时是质检依据——生成完成后要逐条核对条件是否真的被满足，而不是看整体观感。

## 路径 A：条件生成

适用场景是「目标本身不缺样本，缺的是它在不同条件下的样子或组合」。条件可以是天气、光照，也可以是目标类别与边界框。后一种情况不是简单保留原标签：条件框只能作为初始标签，仍要检查生成目标是否出现、边界是否吻合、背景是否被不合理地改变。

下图用道路锥桶展示结构条件的作用。白色框规定目标排布，生成结果要同时满足位置、目标存在性和场景合理性；两张样例只能证明这种控制形式可行，不能代表批量条件满足率。

框控布局还有**组级约束**：单个锥桶都落在给定框内，不代表整组锥桶沿道路方向排列合理，也不代表间距、遮挡层次和密度符合目标场景。更稳的生产顺序是先按道路几何生成候选框组，再让模型完成外观合成；筛选时分别检查目标存在性、框一致性、背景保留和整组交通关系。框重合度只能回答位置问题，不能替代后两项。

Diffusion 与 Flow Matching 是两条主干，差别在于建模对象（离散去噪过程 vs 连续流）以及采样步数与训练稳定性的取舍[@1][@2]。对数据生产而言，比骨干选择更关键的是**条件注入方式**与**能否批量稳定产出**——单张样例好看没有意义，需要的是同一条件下成百上千张都不崩。

条件生成的三种典型失败：

1. **条件不生效**：生成的「雨天」只是整体加噪，没有改变光照、路面反射与可见度；
2. **条件生效但破坏场景**：背景漂移、结构变形，插入的样本在几何上不再对应原场景；
3. **多样性塌缩**：同一条件反复产出高度相似的样本，增加的是数量而不是覆盖。

因此条件生成要报告的不是「生成了多少张」，而是**条件满足率**与**条件内多样性**。

## 路径 B：参考图插入

适用场景是「某个实例本身稀缺而真实」——比如罕见车型、特殊外观设备或道路中的大型动物——需要在指定位置、指定尺度上出现。一条可行的工程路径是用 GLEE 从参考图中提取目标掩码[@8]，再以 Insert Anything 的参考图编辑方式约束局部生成[@7]；道路区域、接地位置、尺度和后筛规则仍需另行设计。

本质上是把**实例的真实外观**与**场景的几何与光照**重新组合，可以分两个层次做：

- **二维合成**：按掩码把实例贴到目标位置，再做光照与阴影调和。成本低，但新视角一致性无从谈起；
- **三维/显式表示**：在可编辑的场景表示中放置资产并重新渲染。3DGS 的显式高斯表示便于这类编辑[@3]，Street Gaussians 的背景—车辆分层更是直接为此设计[@4]。新视角一致性与遮挡关系更可控，代价是依赖场景重建质量。

**放置参数可以给出初始标签，但标签并非天然精确**：目标位置与 BBox 可由条件生成，仍要核对实际像素边界、遮挡和伪影。由此带来两条必须显式约定的事：

1. **标签要覆盖实际渲染出来的像素范围**，包括边缘的抗锯齿过渡带；阴影不应计入 BBox，否则框会随光照变化；
2. **遮挡要有明确口径**：实例被场景物体挡住时，是标记 truncated / occluded，还是直接丢弃这条样本，必须在 schema 里定死。

## 标签与质检

插入路径的标签「免费」，但不等于「正确」。可用的质检清单：

- **条件满足率**：逐条核对生成条件是否被满足；
- **几何与语义一致性**：目标与地面的接触点、尺度是否符合透视，遮挡是否正确；
- **伪影检查**：边缘光晕、复制粘贴痕迹、不自然的重复纹理；
- **标签对齐**：把标签可视化叠加回图像，逐张确认边界；
- **与真实分布的差距**：用真实集上的统计量（目标尺寸分布、位置分布、出现频次）对照，避免生成数据把分布推向某个窄区间。

每条样本都要带来源标记：**真实 / 条件生成 / 插入**。三类混在一起报指标，下游就无法判断收益来自哪里。

批量插入应把「候选」和「可入训样本」分开计数：参考目标提取 → 背景与接地位置选择 → 多候选生成 → 自动过滤 → 人工抽检 → 标签回写与导出。每一步都可能损耗样本；如果只报生成帧数，就会把分割失败、位置不合理和标签错位的成本藏起来。更有意义的分母是**通过质检并实际进入训练的样本数**，再与真实测试集上的边际收益一起看。

## 训练闭环：生成数据怎么进入训练

生成数据的最终判据是下游收益，而且必须分开报告：

1. **真实测试集上的收益**——唯一能说明问题的指标；
2. **长尾子集上的收益**——生成数据最应该改善的地方，若这里没有改善，说明补错了地方；
3. **常见类别是否变差**——生成样本挤占真实分布时的典型症状。

闭环本身要控制变量：同样的真实数据量、同样的训练预算、同样的超参，只改生成数据的混入比例。否则「提升」可能只是训练得更久或见得更多。混入比例本身也是一个需要报告的超参——生成数据占比过高会让模型学到渲染伪影。数据配方里应当把生成样本的来源类别与混入比例一并记下[@5]，这样下游复查时才能区分「换了数据」和「换了配方」。

两个检测结果说明为什么要把验证延伸到真实测试集：一组无人二轮车数据在合成样本量接近原有人标数据量时，检测精度约提高 **4 个绝对百分点**，召回基本稳定；继续加入数据，精度继续上升而召回略降。另一组稀缺动物案例中，原模型无法检出目标，加入合成数据后在三个设置里分别于最远 **76、80、85 m** 处检出。后一组同时改变了数据量和测试距离，因此只能说明特定场景的改善，不能画成严格的数据量消融曲线。两组结果都不能由生成样例的视觉观感代替。

## 如何评价

数据增强不能只依赖视觉观感。需要同时检查几何和语义一致性、生成多样性、标签可用性，以及加入训练后对真实测试集和长尾场景的实际收益。

::: my-take
我认为选择生成路径时应先把**外观条件缺口、空间组合缺口和实例缺口**分开。它们对控制输入和标签的要求不同：外观变化可能继承部分标签，框控排布只能给出初始位置，参考图插入还要处理目标与场景的融合。把这些差别压成一句「生成更多数据」，就会跳过最关键的质量检查。

因此，生成数据的证据链应依次回答：条件是否生效、标签是否与像素对齐、加入训练后真实测试集是否改善。最后一个问题还要报告被牺牲的指标——例如精度提高时召回是否下降。只有这一层成立，生成帧数才有实际意义。
:::

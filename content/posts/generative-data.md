::: note
本文关注生成模型如何服务**长尾场景下的感知训练数据构建**：先在场景联合空间上定位数据缺口，再按缺失轴的支撑情况决定内生重组还是外生引入，之后才是控制条件、标签策略与混入配额，最后通过真实测试集验证价值。图像与结果用于说明这些环节各自能证明什么。
:::

::: tldr
本文面向**长尾场景下的感知模型训练数据构建**。这里说的缺口，都发生在**已采集的数据池**里：训练需要的类别、场景或标签，池子里往往只有少量样本，甚至一条都没有。缺口有两种形态，补法也不同：

- **这一类数据有，但某些类别或某些标签下非常少**：池子里存在，只是覆盖不足，在已有样本上扩增——**内生补**，补法是学习：先从已有数据里学到条件与因子，再重新组合；
- **这一类数据几乎没有**：池子里一条都没有，或极端情况下只剩一两条——从内部学不出来，只能从外部引入素材构造——**外生补**，补法是构造，不需要为这批数据训练变换能力。

区分两者的判据是数据池里有没有可学的支撑，而不是缺多少。两类补法共享同一个下游要求：**生成目标、标签和渲染像素必须对齐**；缺口定位只回答「补哪里」，还要回答「补多少」——目标分布与混入配额。

如果只记一句：生成条件可以提供初始标注依据，却不能自动保证样本可用；最后必须由质检和真实测试集回答它是否有效。
:::

::: question
长尾场景下，当感知模型的训练数据在某个类别、场景或标签上只有极少数样本、甚至一条都没有时，应该自己造还是扩增，又怎样保证产物真的能用于下游任务？
:::

生成式数据增强的目标，是以可控方式补充感知模型训练数据中稀缺、昂贵或组合空间过大的样本。本文处理的是其中的**长尾部分**：某些类别、场景或标签没有样本，或样本少到不足以覆盖它们的真实变化；分布头部已经有充足真实支撑的区域不在讨论范围内。生成质量只是第一步，条件可控性、场景一致性和下游有效性同样重要。当前具身与驾驶模型的规模增长已经把数据量推到主要瓶颈的位置——百万小时级的 scaling law 正是这一判断的体现[@4]——但**「更多数据」和「更对的数据」是两件事**，本文只处理后者。

## 长尾缺口：联合空间上的支撑不足

「数据不够」不是几种互不相同的毛病，而是同一件事在不同尺度上的表现：感知模型的训练集在**场景联合空间**上的支撑不足。这里说的「够不够」只针对**已采集的数据池**：真实世界里存在、但没被采进池子的场景，就算没有。本文也只讨论落在长尾上的缺口——分布头部的类别与条件已有充足真实支撑，不在范围内。

空间可拆成三族轴：

| 轴 | 内容 | 性质 | 对标签的影响 |
| --- | --- | --- | --- |
| 外观轴 | 天气、时段、光照强度与方向、风格 | 作用于整帧，近似连续 | 语义标签大体可沿用，需补可见度等字段 |
| 几何轴 | 相机位姿、目标位置、尺度、朝向、遮挡与排布 | 连续，且决定像素归属 | 位置、框与遮挡标签必须重算，条件值只能作初始标签 |
| 身份轴 | 出现的是哪个类别或实例 | 离散，不可插值 | 新实例要新增标签并定义遮挡口径 |

任何「缺 X」都能写成这个空间里的一块区域：

- **单轴缺口**：缺雨天或夜间，是外观轴上缺一段；
- **组合缺口**：缺某类排布、跨类共现，是两个以上轴的组合区域稀疏——单轴只是它退化到一维的情形；
- **身份缺口**：缺某个类别，是身份轴的边缘分布呈长尾。

分辨率、颜色空间、深度与语义是否同步输出不属于缺口，属于输出约定，放在条件里。

### 定位：缺口落在哪一族轴上

补法不取决于缺口规模，而取决于**缺失的轴在数据池中是否具备可学的支撑**：

| 缺失轴的支撑情况 | 补法 | 对应场景 |
| --- | --- | --- |
| 每个轴都具备可学的支撑（样本稳定，可学到条件与因子），缺的只是它们的组合 | 学因子再重组：条件生成、布局采样 | 场景一 · 内生补 |
| 某一族轴不具备可学的支撑（零样本，或仅一至两条，不足以学习） | 从外部引入真实资产或实例 | 场景二 · 外生补 |

组合缺口可补的充要条件是：**参与组合的每个轴都各自具备可学的支撑**。任一轴不具备可学支撑时，组合问题退化为轴缺失，需转外生补。该判据针对可学性，而非样本数量。

### 选路：数据池 → 可编辑场景 → 生成

- 优先检查数据池中是否已包含目标区域；
- 若需保留某段真实街景的几何与外观、仅替换局部目标或标识，可采用[可编辑世界构建](3dgs-scene-reconstruction.html)；
- 数据池与可编辑资产均无法覆盖时，才进入生成方案。

排序依据是覆盖需求、真实性、可控性与单位有效样本成本，而非技术先进程度。

### 补多少：先定义目标分布

- **目标分布**：各条件占比、类别频次与组合配额；
- **生成量**：由目标分布反推每类样本数量与混入比例；
- **省略该步骤的后果**：生成会按模型自身的先验偏好采样，导致数据分布偏离训练集的真实缺口。

### 形式：写成机器可执行的条件

条件必须机器可执行，不能是自然语言描述。一个可用的 schema 至少包含四组字段：

- **生成条件**：天气、时段、光照强度与方向、风格；
- **空间条件**：目标类别、位置（BBox / 掩码 / 深度平面）、尺度、朝向、遮挡关系；
- **场景约束**：不可改变的区域（保留掩码）、相机参数、地平线与消失点；
- **输出约定**：分辨率、颜色空间、是否同步输出深度或语义标签。

无法写出 schema 时，通常说明需求尚未定义清楚；schema 同时构成质检依据。配额与来源标记须在生成前确定：

- **批次配额**：各条件与类别相对现有真实数据的目标占比、单个条件的样本上限、与真实数据的混入比例区间；
- **来源标记**：每条样本标注为真实 / 条件生成 / 插入，否则三类样本混合统计时收益来源无法归因。

## 场景一 · 内生补（条件生成）：数据有但极少

这一类缺口是「池子里有，但少」：缺失区域涉及的每一族轴都有可学的支撑，目标本身不缺样本，缺的是它在不同条件下的样子或组合。补法落在**学习**上：条件与因子要先从已有样本里学到，再重组生成。条件可以是天气、光照，也可以是目标类别与边界框。后一种情况不是简单保留原标签：条件框只能作为初始标签，仍要检查生成目标是否出现、边界是否吻合、背景是否被不合理地改变。

下图用道路锥桶展示结构条件的作用。白色框规定目标排布，生成结果要同时满足位置、目标存在性和场景合理性；两张样例只能证明这种控制形式可行，不能代表批量条件满足率。

框控布局还有**组级约束**：单个锥桶都落在给定框内，不代表整组锥桶沿道路方向排列合理，也不代表间距、遮挡层次和密度符合目标场景。更稳的生产顺序是先按道路几何生成候选框组，再让模型完成外观合成；筛选时分别检查目标存在性、框一致性、背景保留和整组交通关系。框重合度只能回答位置问题，不能替代后两项。

Diffusion 与 Flow Matching 是两条主干，差别在于建模对象（离散去噪过程 vs 连续流）以及采样步数与训练稳定性的取舍[@1][@2]。对数据生产而言，比骨干选择更关键的是**条件注入方式**与**能否批量稳定产出**——单张样例好看没有意义，需要的是同一条件下成百上千张都不崩。

条件生成的三种典型失败：

1. **条件不生效**：生成的「雨天」只是整体加噪，没有改变光照、路面反射与可见度；
2. **条件生效但破坏场景**：背景漂移、结构变形，插入的样本在几何上不再对应原场景；
3. **多样性塌缩**：同一条件反复产出高度相似的样本，增加的是数量而不是覆盖。

### 标签

标签能否沿用，取决于被改变的是哪一族轴。只改外观轴时，语义标签大体可沿用，但要处理受光照影响的可见度字段；改了几何轴（位置、尺度、朝向、排布）时，位置、框与遮挡标签必须重算，条件值只能作初始标签——条件框规定目标该在哪，不等于像素边界就在哪。

### 质检

报告口径是**条件满足率**与**条件内多样性**，不是生成了多少张。逐条核对：

- **条件满足率**：逐条核对条件是否真的生效，上面三种失败都要在这里被查出来；
- **条件内多样性**：同一条件是否反复产出高度相似的样本，增加的是数量还是覆盖；
- **目标存在性、框一致性与背景保留**：目标是否出现、边界是否吻合、原场景是否被不合理改变；
- **标签对齐**：把标签叠加回图像，逐张确认边界；
- **与真实分布的差距**：用真实集上的统计量（目标尺寸分布、位置分布、出现频次）对照，避免把分布推向某个窄区间；
- **配额核对**：实际产出的条件分布是否命中目标占比。

质检通过不等于有效。一组无人二轮车数据在补充合成样本、使其接近原有人标数据量时，检测精度约提高 **4 个绝对百分点**，召回基本稳定；继续加入数据，精度继续上升而召回略降。收敛判据因此落在下游：既要看真实测试集上的收益，也要看被牺牲的指标，不能用生成样例的观感代替。

### 补充：控制图驱动的生成

框与布局只是控制信号的一种。更一般的做法是把条件写成**结构化的场景表示**：以 HDMap（车道线、可行驶区域、目标框）或 LiDAR 深度图为控制输入，让模型生成同一视角下的真实感画面。下图是 Cosmos-Transfer1-7B 的两组输入与输出[@7]：上排以 HDMap 为条件，下排以 LiDAR 深度为条件；控制图携带的几何与语义正好对应前面说的几何轴，标签也能从控制图推导，而不必从像素反推。

控制式生成并不只服务智能驾驶。把控制图换成任务相关的几何与语义表示——工作空间布局、物体位姿、相机与机械臂位姿——同一套「控制图 → 感知数据」的做法可以用来构造具身场景的数据；输出也不必是单帧，视频序列同样成立。Cosmos3 这类面向物理智能的多模态世界模型就沿这个方向：下图是它前向动力学的输入条件，相机画面与手部位姿被写成控制信号，模型据此预测未来画面[@8]。决定数据能不能用的仍然不是模型：控制信号写得多细，决定了需求能被表达多少、标签能覆盖多大范围。

## 场景二 · 外生补（参考图插入）：数据几乎没有

这一类缺口出在身份轴上：目标类别在已采集的数据池里几乎没有——一条都没有，或极端情况下只有一两条，比如罕见车型、特殊外观设备、道路中的大型动物——而它需要在指定位置、指定尺度上出现。这类信息不在训练集里，学习补不回来，只能从外部引入。补法落在**构造**上：不为这批数据训练变换能力，只调用现成的预训练模型，把外部素材按放置规则合成进场景。

引入之前先要有一个可检索的**资产库**：前景实例与背景底图都要先前留存，否则「想插入」也找不到素材。来源不必都是自有采集——互联网照片与自有场景照片可以混用，两者都是 2D 图像，成本低、覆盖广。

有了资产，生产走**单视角的 2D 插入**：用 GLEE 从参考图里取出目标掩码[@6]，由规则估计给出它在场景中的落点、尺度与朝向，换算成一张插入掩码，再交给 Insert Anything 完成局部合成。只做一个视角——不追求新视角一致性，代价是所有自洽性都要在这一个视角里检查。

落点与尺寸不依赖精确标定，而是一套**基于规则的估计**：用相机内外参、地平线与消失点，加上目标与地面的接触点，推一个粗略的深度、朝向与尺寸，再换算成插入掩码的位置与大小。规则估出来的量会直接写进标签，所以接地与透视必须逐张核对；估计偏差是这条路线的主要误差来源。

Insert Anything 走的是 DiT 上的 in-context editing[@5]：把抠掉背景的参考实例与带插入掩码的目标图按宽度拼成一张 diptych（参考面板掩码全 0、插入区域全 1），VAE 编码后与噪声在通道维拼接送入 DiT，掩码区域在去噪时直接 attend 参考面板的 token，身份细节由这次跨面板注意力继承，不需要 ControlNet 一类附加分支。模型在 AnyInsertion（约 16 万对、掩码与文本两种 prompt）上训练一次，之后只做推理：接口是「参考实例 + 带掩码的目标图」，不针对这批数据再训练，也不做逐实例微调。

### 标签

引入新实例属于身份轴上的变化，标签是新增而不是沿用。放置参数可以给出初始位置，但**标签并非天然精确**——目标位置与 BBox 可由条件生成，仍要核对实际像素边界、遮挡与伪影。由此带来两条必须显式约定的事：

1. **标签要覆盖实际渲染出来的像素范围**，包括边缘的抗锯齿过渡带；阴影不应计入 BBox，否则框会随光照变化；
2. **遮挡要有明确口径**：实例被场景物体挡住时，是标记 truncated / occluded，还是直接丢弃这条样本，必须在 schema 里定死。

插入样本的标签「免费」，但不等于「正确」：它来自放置参数，而不是来自真实观测。

### 评估

批量插入要把「候选」和「可入训样本」分开计数：参考目标提取 → 背景与接地位置选择 → 多候选生成 → 自动过滤 → 人工抽检 → 标签回写与导出。每一步都会损耗样本，只报生成帧数会把分割失败、位置不合理与标签错位的成本藏起来；有意义的分母是**通过质检并实际进入训练的样本数**。进入这个分母之前，候选还要先过几何与伪影检查：接地与透视是否符合、遮挡是否正确、是否有边缘光晕、复制粘贴痕迹或不自然的重复纹理。

最终判据是下游收益，而且必须分开报告：真实测试集上的收益、长尾子集上的收益（生成数据最应该改善的地方，若这里没有改善，说明补错了地方）、常见类别是否变差（生成样本挤占真实分布时的典型症状）。闭环要控制变量——同样的真实数据量、训练预算与超参，只改生成数据的混入比例，否则「提升」可能只是训练得更久；混入比例本身也是要报告的超参，数据配方里应把来源类别与混入比例一并记下[@3]，实际比例与目标配额的偏差也要和收益一起报。

一组稀缺动物案例中，原模型无法检出目标，引入合成数据后在三个设置里分别于最远 **76、80、85 m** 处检出。该结果同时改变了数据量与测试距离，因此只能说明特定场景的改善，不能画成严格的数据量消融曲线；单张样例也不代表后筛通过率。

## 小结

回到两个场景的共同点：这类方案要交付的不只是图像，而是**媒体信息加标签**。改变一帧的天气、把一个实例插进指定位置，真正的产出是同时得到一份可以直接用于训练的标注——类别、位置、尺度与遮挡口径。只有像素而没有可信标签，感知模型的训练拿不到增量；反过来，标签再全，像素不真实，学到的也只是标注的偏差。

**可控正是为此服务的，也是这两条路线的共同目标。** 基于框或语义描述的条件生成，把「目标出现在哪、长什么样」写成可执行的条件；基于特定位置的参考图插入，把「实例放在哪、多大、怎么接地」写成放置参数。控制条件本身就是初始标注的依据，这也是条件 schema 与批次配额必须在生成之前定下来的原因：不可控的生成即使好看，也给不出可用的标签。

但可控只保证控制被响应，不保证标注可信：条件写进了 schema，仍要逐条核对它是否生效；控制条件给出了初始标签，仍要核对标签是否覆盖真实渲染出来的像素。两个场景因此都在方案之后紧跟一段验收——前者看质检，后者看评估。

技术上反而没有太多难点：模型、后筛与标签回写都是现成组件，单视角的 2D 插入尤其如此。更关键的是**问题定义**——要补的是哪一族轴上的缺口，以及能用什么控制信号把这个需求表达出来；控制信号能写到多细（掩码、深度、位姿、尺度、遮挡关系），决定了生成能被约束到什么程度，也决定了标签能覆盖到什么程度。

::: my-take
我认为把长尾缺口写成「三种类型」会掩盖它其实是同一个问题：训练集在场景联合空间上的支撑不足。真正决定补法的是缺失的那一族轴在数据池里有没有可学的支撑——各轴都有可学的支撑、缺的只是组合，就可以学因子再重组；某族轴几乎没有可学样本，学习补不回来，只能从外部引入真实资产。

因此，生成数据的证据链应依次回答：缺口落在哪一族轴上、条件是否生效、标签是否与像素对齐、加入训练后真实测试集是否改善。最后一问还要报告被牺牲的指标——例如精度提高时召回是否下降。只有这一层成立，生成帧数才有实际意义。

图像与视频两种模态上，更多、更好的方法在持续出现。真正难、也最容易被低估的是**控制信号的准备与定义**——把场景需求拆成模型能接收的条件，并保证这些条件在真实数据里可获取、可标注、可复现。有现成的模型可用固然最好；如果没有，就要在这个定义之下再收集一批数据把模型训练出来：控制信号怎么定，决定了要采什么、标什么，也决定了这套能力以后能不能复用。
:::

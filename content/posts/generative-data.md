::: note
本文关注生成模型如何服务**长尾场景下的感知训练数据构建**：先在场景联合空间上定位数据缺口，再按缺失轴的支撑情况决定内生重组还是外生引入，之后才是控制条件、标签策略与混入配额，最后通过真实测试集验证价值。图像与结果用于说明这些环节各自能证明什么。
:::

::: tldr
本文面向**长尾场景下的感知模型训练数据构建**：训练需要的类别、场景或标签，训练集里往往完全没有，或只有极少数样本。缺口有两种形态，补法也不同：

- **这一类数据有，但某些类别或某些标签下的量非常少**：存量覆盖不足，需要在已有样本上扩增——**内生补**，补法是学习：先从已有数据里学到条件与因子，再重新组合；
- **这一类数据完全没有**：某个类别在存量里不存在，从内部学不出来，只能从外部引入素材构造——**外生补**，补法是构造，不需要为这批数据训练变换能力。

区分两者的判据是存量里有没有支撑，而不是缺多少。两类补法共享同一个下游要求：**生成目标、标签和渲染像素必须对齐**；缺口定位只回答「补哪里」，还要回答「补多少」——目标分布与混入配额。

如果只记一句：生成条件可以提供初始标注依据，却不能自动保证样本可用；最后必须由质检和真实测试集回答它是否有效。
:::

::: question
长尾场景下，当感知模型的训练数据在某个类别、场景或标签上完全没有、或只有极少数样本时，应该自己造还是扩增，又怎样保证产物真的能用于下游任务？
:::

生成式数据增强的目标，是以可控方式补充感知模型训练数据中稀缺、昂贵或组合空间过大的样本。本文处理的是其中的**长尾部分**：某些类别、场景或标签没有样本，或样本少到不足以覆盖它们的真实变化；分布头部已经有充足真实支撑的区域不在讨论范围内。生成质量只是第一步，条件可控性、场景一致性和下游有效性同样重要。当前具身与驾驶模型的规模增长已经把数据量推到主要瓶颈的位置——百万小时级的 scaling law 正是这一判断的体现[@6]——但**「更多数据」和「更对的数据」是两件事**，本文只处理后者。

## 长尾缺口：联合空间上的支撑不足

「数据不够」不是几种互不相同的毛病，而是同一件事在不同尺度上的表现：感知模型的训练集在**场景联合空间**上的支撑不足。本文讨论的缺口都落在长尾上：分布头部的类别与条件已有充足真实支撑，不属于本文范围，因此问题可以统一写成这个空间里稀疏或为空的区域。它可拆成三族轴：

| 轴 | 内容 | 性质 | 对标签的影响 |
| --- | --- | --- | --- |
| 外观轴 | 天气、时段、光照强度与方向、风格 | 作用于整帧，近似连续 | 语义标签大体可沿用，需补可见度等字段 |
| 几何轴 | 相机位姿、目标位置、尺度、朝向、遮挡与排布 | 连续，且决定像素归属 | 位置、框与遮挡标签必须重算，条件值只能作初始标签 |
| 身份轴 | 出现的是哪个类别或实例 | 离散，不可插值 | 新实例要新增标签并定义遮挡口径 |

任何「缺 X」都能写成这个空间里支撑不足的一块区域：缺雨天或夜间是外观轴上缺一段；缺某类排布、跨类共现是多个轴的组合区域稀疏——**单轴缺口只是组合缺口退化到一维的情形**；缺某个类别是身份轴的边缘分布呈长尾。分辨率、颜色空间、深度与语义是否同步输出这类要求不属于缺口，属于输出约定，放在 schema 里。

把缺口写在轴上，比按「天气 / 布局 / 类别」并列更直接，因为它顺手给出一条判据——**补法不取决于缺口多大，而取决于缺失的轴在存量里有没有支撑**：

| 缺失轴的支撑情况 | 补法 | 对应场景 |
| --- | --- | --- |
| 每个轴都有支撑（哪怕只有边缘样本），缺的只是它们的组合 | 学因子再重组：条件生成、布局采样 | 场景一 · 内生补 |
| 某一族轴完全没有支撑（该类别从未出现、该外观条件在训练集里不存在） | 从外部引入真实资产或实例 | 场景二 · 外生补 |

组合缺口可补的充要条件是：**参与组合的每一个轴都各自有支撑**。若任一轴为空，组合问题就退化成轴缺失，必须走外生补。这也是「样本少」与「样本为零」在方法上分开的地方：判断依据是轴上有没有支撑，不是样本量阈值。

对应到更大的数据选择顺序：先查存量真实数据是否已有目标区域；若要保留某段真实街景的几何与外观、只改变局部目标或标识，可考虑[可编辑世界构建](3dgs-scene-reconstruction.html)；存量与可编辑资产都覆盖不了要补的区域，或需要跨许多背景扩展目标组合时，再进入本文的生成方案。这是按**覆盖需求、真实性、可控性和单位有效样本成本**选工具，不是给几种技术排先进程度。

定位之后还有两个问题：**补多少**，以及**怎么把要求写成机器可执行的形式**。

**补多少**是配额问题：先写出目标分布（各条件占比、类别频次与组合配额），再反推每类要生成多少、以什么比例混入。少了这一层，生成会沿模型自己的偏好填：拿生成样本去填本来已有充足真实支撑的区域，增加的不是覆盖，而是**把分布往生成模型的偏好上拉**。

条件则必须是机器可执行的，不能是一句自然语言描述。一个够用的条件 schema 至少包含四组字段：

- **生成条件**：天气、时段、光照强度与方向、风格；
- **空间条件**：目标类别、位置（BBox / 掩码 / 深度平面）、尺度、朝向、遮挡关系；
- **场景约束**：不可改变的区域（保留掩码）、相机参数、地平线与消失点；
- **输出约定**：分辨率、颜色空间、是否需要同步输出深度或语义标签。

Schema 写不出来，说明这批数据的需求还没定义清楚。它同时是质检依据——生成完成后要逐条核对条件是否真的被满足，而不是看整体观感。**批次配额**则定义这批数据在训练集里占什么位置：各条件与类别相对存量真实数据的目标占比、单个条件的样本上限、与真实数据的混入比例区间。条件满足率回答「这一条对不对」，配额回答「这一批该不该有这么多」。无论走哪条补法，每条样本都要带来源标记：**真实 / 条件生成 / 插入**——三类混在一起报指标，下游就无法判断收益来自哪里。

## 场景一 · 内生补（条件生成）：数据有但极少

这一类缺口的共同点是：缺失区域涉及的每一族轴都有支撑，目标本身不缺样本，缺的是它在不同条件下的样子或组合。补法落在**学习**上：条件与因子要先从已有样本里学到，再重组生成。条件可以是天气、光照，也可以是目标类别与边界框。后一种情况不是简单保留原标签：条件框只能作为初始标签，仍要检查生成目标是否出现、边界是否吻合、背景是否被不合理地改变。

下图用道路锥桶展示结构条件的作用。白色框规定目标排布，生成结果要同时满足位置、目标存在性和场景合理性；两张样例只能证明这种控制形式可行，不能代表批量条件满足率。

框控布局还有**组级约束**：单个锥桶都落在给定框内，不代表整组锥桶沿道路方向排列合理，也不代表间距、遮挡层次和密度符合目标场景。更稳的生产顺序是先按道路几何生成候选框组，再让模型完成外观合成；筛选时分别检查目标存在性、框一致性、背景保留和整组交通关系。框重合度只能回答位置问题，不能替代后两项。

Diffusion 与 Flow Matching 是两条主干，差别在于建模对象（离散去噪过程 vs 连续流）以及采样步数与训练稳定性的取舍[@1][@2]。对数据生产而言，比骨干选择更关键的是**条件注入方式**与**能否批量稳定产出**——单张样例好看没有意义，需要的是同一条件下成百上千张都不崩。

条件生成的三种典型失败：

1. **条件不生效**：生成的「雨天」只是整体加噪，没有改变光照、路面反射与可见度；
2. **条件生效但破坏场景**：背景漂移、结构变形，插入的样本在几何上不再对应原场景；
3. **多样性塌缩**：同一条件反复产出高度相似的样本，增加的是数量而不是覆盖。

### 标签

标签能否沿用，取决于被改变的是哪一族轴。只改外观轴时，语义标签大体可沿用，但要处理受光照影响的可见度字段；改了几何轴（位置、尺度、朝向、排布）时，位置、框与遮挡标签必须重算，条件值只能作初始标签——条件框规定目标该在哪，不等于像素边界就在哪。

### 质检

报告口径是**条件满足率**与**条件内多样性**，不是生成了多少张。逐条核对：

- **条件满足率**：逐条核对条件是否真的生效，上面三种失败都要在这里被查出来；
- **条件内多样性**：同一条件是否反复产出高度相似的样本，增加的是数量还是覆盖；
- **目标存在性、框一致性与背景保留**：目标是否出现、边界是否吻合、原场景是否被不合理改变；
- **标签对齐**：把标签叠加回图像，逐张确认边界；
- **与真实分布的差距**：用真实集上的统计量（目标尺寸分布、位置分布、出现频次）对照，避免把分布推向某个窄区间；
- **配额核对**：实际产出的条件分布是否命中目标占比。

质检通过不等于有效。一组无人二轮车数据在补充合成样本、使其接近原有人标数据量时，检测精度约提高 **4 个绝对百分点**，召回基本稳定；继续加入数据，精度继续上升而召回略降。收敛判据因此落在下游：既要看真实测试集上的收益，也要看被牺牲的指标，不能用生成样例的观感代替。

## 场景二 · 外生补（参考图插入）：数据完全没有

这一类缺口出在身份轴上：目标类别在存量中实例太少甚至从未出现——罕见车型、特殊外观设备、道路中的大型动物——而它需要在指定位置、指定尺度上出现。这类信息不在训练集里，学习补不回来，只能从外部引入。补法落在**构造**上：不为这批数据训练变换能力，而是把外部素材按放置规则构进场景。

引入之前先要有一个可检索的**资产库**：前景实例与背景底图都需要先前留存，否则「想插入」也找不到素材。来源不必都是自有采集——互联网照片与自有场景照片可以混用，这一层以 **2D 图像**为主，成本低、覆盖广；只有当插入结果需要新视角一致性时，才需要重建资产或外部模型这条更重的路线，见[可编辑世界构建](3dgs-scene-reconstruction.html)。

有了资产，一条可行的工程路径是用 GLEE 从参考图中提取目标掩码[@8]，再以 Insert Anything 的参考图编辑方式约束局部生成[@7]；道路区域、接地位置、尺度和后筛规则仍需另行设计。

本质上是把**实例的真实外观**与**场景的几何与光照**重新组合，可以分两个层次做：

- **二维合成**：按掩码把实例贴到目标位置，再做光照与阴影调和。成本低，但新视角一致性无从谈起；
- **三维/显式表示**：在可编辑的场景表示中放置资产并重新渲染。3DGS 的显式高斯表示便于这类编辑[@3]，Street Gaussians 的背景—车辆分层更是直接为此设计[@4]。新视角一致性与遮挡关系更可控，代价是依赖场景重建质量。

### 标签

引入新实例属于身份轴上的变化，标签是新增而不是沿用。放置参数可以给出初始位置，但**标签并非天然精确**——目标位置与 BBox 可由条件生成，仍要核对实际像素边界、遮挡与伪影。由此带来两条必须显式约定的事：

1. **标签要覆盖实际渲染出来的像素范围**，包括边缘的抗锯齿过渡带；阴影不应计入 BBox，否则框会随光照变化；
2. **遮挡要有明确口径**：实例被场景物体挡住时，是标记 truncated / occluded，还是直接丢弃这条样本，必须在 schema 里定死。

插入样本的标签「免费」，但不等于「正确」：它来自放置参数，而不是来自真实观测。

### 评估

批量插入要把「候选」和「可入训样本」分开计数：参考目标提取 → 背景与接地位置选择 → 多候选生成 → 自动过滤 → 人工抽检 → 标签回写与导出。每一步都会损耗样本，只报生成帧数会把分割失败、位置不合理与标签错位的成本藏起来；有意义的分母是**通过质检并实际进入训练的样本数**。进入这个分母之前，候选还要先过几何与伪影检查：接地与透视是否符合、遮挡是否正确、是否有边缘光晕、复制粘贴痕迹或不自然的重复纹理。

最终判据是下游收益，而且必须分开报告：真实测试集上的收益、长尾子集上的收益（生成数据最应该改善的地方，若这里没有改善，说明补错了地方）、常见类别是否变差（生成样本挤占真实分布时的典型症状）。闭环要控制变量——同样的真实数据量、训练预算与超参，只改生成数据的混入比例，否则「提升」可能只是训练得更久；混入比例本身也是要报告的超参，数据配方里应把来源类别与混入比例一并记下[@5]，实际比例与目标配额的偏差也要和收益一起报。

一组稀缺动物案例中，原模型无法检出目标，引入合成数据后在三个设置里分别于最远 **76、80、85 m** 处检出。该结果同时改变了数据量与测试距离，因此只能说明特定场景的改善，不能画成严格的数据量消融曲线；单张样例也不代表后筛通过率。

::: my-take
我认为把长尾缺口写成「三种类型」会掩盖它其实是同一个问题：训练集在场景联合空间上的支撑不足。真正决定补法的是缺失的那一族轴在存量里有没有支撑——各轴都有支撑、缺的只是组合，就可以学因子再重组；某族轴整个是空的，学习补不回来，只能从外部引入真实资产。把这条判据写清楚，「样本少」和「样本为零」就不会被压成一类。

因此，生成数据的证据链应依次回答：缺口落在哪一族轴上、条件是否生效、标签是否与像素对齐、加入训练后真实测试集是否改善。最后一问还要报告被牺牲的指标——例如精度提高时召回是否下降。只有这一层成立，生成帧数才有实际意义。
:::

::: tldr
重建一个场景和**让这个场景可被使用**是两件难度不同的事。3DGS 让「可观看」变得便宜，但一旦场景要被拿去编辑资产、生成训练数据或驱动闭环仿真，问题就从渲染质量变成了**可信度**：几何对不对、编辑后还自不自洽、生成的标签能不能当标签用。

本文先给基线：Street Gaussians 把街景拆成背景与车辆两层，让场景可渲染、可编辑。基线在三个地方不够用——**监督、地面、新视角**，三项改进依次针对它们；之后才是这套框架的使用：训练数据生成、交互可运行。**错误会沿这条链继续传**：渲染图看不出几何错误，几何错误会变成标签错误，标签错误最终变成策略的 reward 错误。

如果只记一句：**闭环能跑通是门槛，不是结论**——它交出的是接口、延迟预算和失效边界。
:::

::: question
一个重建场景如何从「可观看」走到「可编辑、可生产数据、可闭环交互」？
:::

[3D Gaussian Splatting（3DGS）](https://arxiv.org/abs/2308.04079)用可优化的三维高斯作为显式场景表示，将多视角图像拟合成可以快速渲染的新视角[@1]。做可编辑合成时，除了外观质量，还必须考虑动态物体、视角缺失和编辑后的几何一致性。

三项改进不是并列的功能清单，而是从基线失效处依次长出来的：**先修输入**（监督），**再修地基**（地面），**然后把监督扩到没有像素的视角**（新视角）。阅读顺序即此顺序，每一小节末尾交代该项的判据与边界；使用部分的两个小节放在三项之后，讲这套框架怎么被使用。

## 基线：Street Gaussians

Street Gaussians 提供基线表示：它把街景拆成背景与运动车辆两层，让场景可渲染、可编辑，也是后面三项改进的参照系。

[Street Gaussians](https://arxiv.org/abs/2401.01339) 的背景是道路视频中的车辆在运动，而早期动态街景 NeRF 类方案训练和渲染较慢。它把背景与前景车辆组织为不同的高斯点云，给点云附加语义信息，利用可优化的跟踪位姿和时间相关的外观表示处理车辆动态。显式的背景—车辆组合使新视角渲染、车辆替换和位置编辑更自然[@2]；其适用前提仍包括可靠的相机与物体运动估计。整体流程如下图。

## 基线的三个缺口

基线在三类条件下会失效，这也是三项改进各自针对的问题：

1. **监督**：标定、同步、位姿与点云深度都来自观测；错误在渲染图上几乎不可见，却决定了整条链路的误差下限。
2. **地面**：弱纹理路面容易欠拟合，漂浮与过度拉伸的高斯难以自查；地面高度一旦偏，资产放置与策略学习的 reward 会带着同一个偏差。
3. **新视角**：优化目标只覆盖训练视角，换到没拍到的位姿就没有监督，空洞与重影只能被现有高斯勉强解释。
三项处理完，才轮到这套框架的使用：先做数据生成，再交互运行。

### 监督：先把测量本身做可信

重建的输入是观测，不是真值。相机内外参、多传感器时间同步、位姿估计、滚动快门、以及运动物体对静态假设的破坏，共同构成了误差下限。这一步容易被跳过，因为**它的失败在渲染图上几乎不可见**：一个位姿估计偏移的场景，依然能渲染出漂亮的图像，只是几何整体被扭曲了。

从原始驾驶片段到可训练输入，中间还有一层容易被误认为「数据预处理」的几何工作：多相机图像与 LiDAR 按时间戳对齐，统一坐标系并筛掉异常帧；再用多视角特征匹配、SfM 与 Bundle Adjustment 检查和优化相机位姿。最终以**相机位姿与时间戳**为索引，把 RGB、内外参、点云和动态对象轨迹关联起来。这样，同一个像素所接受的颜色与深度监督才有共同的时空基准；否则后面即使增加深度损失，也可能是在优化互相冲突的观测。

> **一条纪律：训练视角的渲染质量不能作为几何正确性的证据。** 3DGS 的优化目标本身就包含拟合训练视角，用拟合结果证明拟合成立是循环论证。

**一个具体失败模式是错误的点云深度监督。** 如果车后方的背景点被投影到车体区域，错误深度会把高斯拉向不该出现的位置，造成前后景穿透。下图是同一车辆在深度监督修复前后的渲染对照：车体透明现象得到缓解。它说明监督质量会影响局部几何，却不能单凭这组图证明整个场景的几何精度。

### 地面：结构、尺度与监督来源

这是行车场景，地面质量的优劣直接决定这个场景能不能用：车辆始终贴在地面上行驶，地面和主体结构也是后面所有环节的地基。路面是大面积弱纹理区域，在高斯表示下容易欠拟合，也容易出现漂浮或过度拉伸的高斯；地面高度一旦不准，后续资产放置与策略学习的 reward 都会带着同一个偏差。

这一步要做的主要是给结构加约束：用平面或道路先验、语义分割结果约束地面区域；把地面拟合残差单独可视化出来（而不是混在整体 loss 里）；并且明确**场景尺度的来源**——尺度是从标定来的、从已知物体尺寸推的，还是从单目深度估计来的。这三者的可信度完全不同，必须在数据卡里写清楚。

弱纹理地面尤其需要解释**监督从哪里来**。下面的可视化把地面 RGB 与分割、重建深度与法向、Mesh 提供的深度与法向并排展示：连续表面能为稀疏点云覆盖不到的区域提供更稠密的几何约束。这张图展示的是监督构造，不是优化前后指标。

这里深度与法向解决的是两类不同的错误：**深度**约束地面的空间位置，**法向**约束局部朝向与连续性。只压低 RGB 误差，平坦道路仍可能被一组从训练视角看似正确、实际起伏的高斯解释；只做法向平滑，又可能得到一块平整但高度错误的路面。稠密 Mesh 监督因此应与 RGB 和有效点云监督联合使用，并检查 Mesh 本身是否把原有几何错误扩散到了未观测区域。

### 新视角生成：渲染—修复—回灌

新视角这一缺口没有现成像素可监督，只能先把内容补出来，再当作伪监督用。

[ReconDreamer](https://arxiv.org/abs/2411.19548) 是这条路线上的公开参照。它面向驾驶场景的新轨迹渲染（3 米、6 米横向偏移与变道），主循环是「渲染 → 修复 → 回灌」：渲染新轨迹视角，由 DriveRestorer 修复重影，修复后的视频再与原始视频一起优化重建模型，迭代到收敛；修复器以退化渲染帧为控制条件，训练数据取自不同训练阶段的渲染采样，并用掩码强调天空与远处[@6]。整体流程如下图。

<figure class="frontier-figure"><a href="../assets/3dgs-recondreamer-pipeline.webp" title="查看原图"><img src="../assets/3dgs-recondreamer-pipeline.webp" alt="ReconDreamer 流程：新轨迹渲染视频与噪声图像、3D 框序列、HDMap 序列一起送入 DriveRestorer，解码出修复视频；修复视频按数据采样概率与原始轨迹视频一起回灌动态场景重建，再继续渲染新的轨迹视角。"></a><figcaption><strong>图 · ReconDreamer 的在线修复与渐进数据更新</strong>。左侧为渐进轨迹采样与渲染；中部 DriveRestorer 以噪声图像、新轨迹渲染视频、3D 框序列与 HDMap 序列为输入，解码出修复后的新轨迹视频；右侧按数据采样概率把原始轨迹视频与 1.5 m / 3 m 变道修复视频回灌到动态场景重建。点击可看原图。图源：ReconDreamer 论文。</figcaption></figure>

本链路采用同一循环：

1. **首轮重建**：在原始视角上完成一轮重建，场景只在这批视角上成立；
2. **采样新视角**：在外侧采样新位姿，渲染出带空洞、拉伸与重影的图；
3. **扩散修复**：用扩散模型还原这些视角的 RGB；
4. **伪监督回灌**：把修复结果当作伪监督，与原视角一起优化；
5. **迭代外扩**：表示更新后再扩一圈，直到指标不再改善。

每轮只扩一小圈是有意为之：外扩越远，可见像素越少、修复模型的自由度越大；超出「上一步几何还能支撑」的范围，监督就退化为纯生成。

修复这一步在本链路里需要自己训练一个扩散模型来完成：它接收带空洞、拉伸与重影的渲染图，输出可回灌的 RGB。也就是说，这条链路除了场景表示本身，还要额外维护一个生成模型，它的训练与推理开销都要计入新视角外扩的预算。

多轮扩张放大了三类风险：

1. **误差累积**：第 N 轮伪标签成为第 N+1 轮几何的一部分，生成错误被固化后不再以空洞形式暴露，也失去了「这里不确定」的信号；
2. **置信度衰减**：外扩越远，可对齐的真实像素越少，伪标签中生成先验占比越高，内外圈指标不是同一个量；
3. **自证循环**：输入完全来自上一轮渲染会持续强化偏差，每轮保留原始观测做回归校验是最低要求。

停止准则因此不是「扩到覆盖为止」，而是外扩一圈后保留视角上的指标是否仍在改善；每条样本带轮次与来源标记（真实观测 / 插值视角 / 第 N 轮修复），按轮次与外扩圈分层报告，这与「训练数据生成」一小节的来源分层是同一条纪律[@3]。补全后仍需单独做一次只统计有效区域的几何检查——补全训练**会掩盖几何错误，而不是修复它**：地面高度或尺度上的错误被填平后指标变好，错误仍在，只是不再以空洞的形式出现。

## 场景的两种使用方式

前三项改进让场景可被信任，接下来才是这套框架的使用方式：拿它生成训练数据，以及把它接成可交互环境。两者的检查重点不同，但都依赖同一件事——场景本身是否可信。

### 训练数据生成

训练数据生成有两条路子：**在同一个场景里换视角**，即采样新位姿重渲染；**改变场景本身**，即场景编辑，含资产增删与交通流增删。前者只动相机，后者动内容。地面误差会一路传到这里——同一资产放在同一视角下，错误深度可能造成遮挡或下陷；修复后资产才更可能完整呈现。因此，验证地面质量不能只看道路本身，还要看它能否承载后续操作。

<figure class="frontier-figure"><img src="../assets/3dgs-asset-placement.jpg" alt="同一街景中添加资产的前后对照，地面修复后资产呈现更完整。"><figcaption><strong>案例 · 地面修复对资产放置的影响</strong>。图像提供局部定性证据；资产接地、遮挡和多视角一致性仍需分别检查。</figcaption></figure>

改变场景的前提是**可分离**：把可动物体与静态背景分成可以独立操作的两部分，才能替换、删除或插入资产，也才能按需要调整交通流的疏密。Street Gaussians 的显式背景—车辆分层正是为了让这类编辑更自然[@2]——这也是显式表示相对隐式表示的优势所在。

一次编辑是否可信，至少要看四件事：

1. **原视角一致性**：编辑后从原来的相机视角看，背景是否仍然自洽；
2. **新视角合理性**：换到没见过的视角，遮挡关系是否正确（这最能暴露只做了二维拼贴的方案）；
3. **光照与阴影自洽**：插入的资产是否与场景光照方向一致，阴影是否落在正确的地面上；
4. **不破坏性**：编辑是否影响了那些原本正确的区域。

换视角这一侧不需要编辑，只动相机：抽帧、选视角，在已重建的场景里采样新位姿重渲染，就得到新的 (图像, 标签) 对。合成数据的价值取决于两件事：**标签是否与渲染真正对齐**（bbox、深度、语义分割是否与高斯表示的几何严格一致），以及**是否引入了只存在于渲染中的伪影**（高光、漂浮高斯、边缘飞点）——伪影一旦进入训练集，就会被模型当成真实分布学走。

因此每条样本都要带来源标记：**真实观测 / 插值视角 / 生成补全**。三者的可信度不同，不能混在一张表里报指标。这与会话式数据体系那篇的「按来源分层」是同一条原则[@3]：数据配方里不写清来源，下游就无法判断一个提升是来自数据量还是来自引入了偏差。

编辑后的场景重新渲染出的样本，还要对照保留视角验证新视角质量、物体位置与遮挡是否与编辑意图一致；生成补全的区域额外记录不确定性，避免把合成标签当作真实观测使用。

### 交互可运行：仿真接入与策略学习 PoC

把重建场景接成可交互环境，需要它能加载、能按动作推进状态、并把新观测交给策略。本链路的做法是把环境做成**独立进程的服务**：场景资产、状态推进和渲染都在服务侧，策略侧只持一个客户端，通过 RPC 或共享内存在同一条 step 契约上交互。这样切开的理由是两侧的替换频率不同——渲染是重的那一侧，策略训练则需要能独立重启、换设备和换并行度，而接口不必跟着改。闭环本身是四个环节首尾相接：动作进入 → 环境状态变化 → 新观测返回 → 策略收到反馈；策略的动作真的改变环境状态，新观测也真的来自改变后的状态。

服务侧的职责有三块。**场景资产**：每段 clip 对应一份逐场景优化的 3DGS 表示，加载一份就得到一个可交互场景，重置即回到该 clip 的起点。**状态推进**：动作进来后经运动学模型（自行车模型一类）积分到下一自车位姿，这是环境里唯一的动力学假设。**渲染**：按新位姿实时渲染 RGB 作为对外的观测出口——策略拿到的是图，不是场景内部的几何或标注。

策略侧是一个普通训练循环：观测编码把 RGB 变成特征，策略头输出动作，动作经同一条契约回到服务侧，得到的 (观测, 动作, 反馈) 三元组进回放缓冲，按批更新后再进入下一轮交互。策略不读场景内部状态，因此换策略结构不用动环境，换环境实现也不用动策略。用一个小规模 CNN+MLP 策略跑通这条通路，验证的就是这一点：三元组能从合成场景持续产出，并被下一轮训练直接消费。

契约本身很薄：加载与重置、step、关闭。把环境做成服务之后，训练能不能跑起来就取决于两件事：一步的端到端时延（状态推进 + 渲染 + 传输）是否落进策略训练可接受的窗口，以及同一动作在同一状态下是否返回同一观测。这是这一步真正的交付物——不是一张分数表，而是一套**可复用的接口与预算**；链路闭合之后，要动的更多是策略的规模与结构，接口可以复用。

这条路线在工业界已经有走完整流程的实现，可以当作本链路的对照样本。地平线的 RAD 用 3DGS 重建真实驾驶片段，把重建结果接成以传感器观测为接口的闭环环境，再在其中训练端到端策略：先做感知预训练，再用模仿学习预训练规划头，最后在重建场景里用 RL 与 IL 联合后训练；动作经自行车模型推到下一步位姿，奖励围绕动态碰撞、静态碰撞、横向位置偏差与朝向偏差设计，发生碰撞或偏差超过阈值就终止 episode[@7][@8]。它用 4305 个关键场景重建出训练与评测环境（3968 / 337），相对纯模仿学习把碰撞率降到约三分之一[@7][@8]。把 RAD 的三步拆开与本链路对照，环境侧的要求几乎完全一致：逐场景重建 → 可重置、能按动作推进并返回观测的环境 → 策略在闭环里训练。差别在规模与工程完整度，不在链路形态。

这条路线的效果有公开 demo 可以对照：同一个转弯片段，上面是纯模仿学习训练出的策略，下面是 RAD 用 RL 后训练之后的策略。转弯同时考验横向动作与纵向速度，是这类闭环策略最容易分化的工况。

RAD 的工程取舍也印证了本文的几条纪律。它把 IL 留作正则项、并在碰撞或偏差过大时直接终止 episode——公开解读给出的原因是，触发这些事件后重建环境会产生带噪的传感器数据，对 RL 训练有害[@8]；这与「外扩越远、监督越退化为纯生成」是同一个现象，处理方式也一样：把不确定的部分圈出来单独报告。它把评测放在 337 个未参与训练的场景上，也就是「保留视角」在场景级别的版本。它公开的边界同样具体：这类环境本质上仍是 log replay、缺少真实交互，非刚性行人、视野外信息与低光照的渲染质量有限[@8]。这些限制决定了下游能训出什么，而本链路在小规模上先量的是它的上游——环境能不能加载、能不能按同一规则推进、时延能不能被训练循环接受。

同一条路线上还有几种相邻的做法：DreamerV3 用同一套世界模型跨多个域训练控制策略[@4]，WALL-WM 把世界模型与语言—动作学习放在一起[@5]，ReconDreamer 用在线修复把新轨迹渲染接进闭环仿真[@6]。它们的评测各自独立设计，任务与规模不同，指标不能与本链路横向比较；能对齐的仍然是链路形态——**闭环能不能跑，与闭环跑得好不好，是两个必须分开报告的问题**。RAD 已经在后者上给出证据，本链路这一步先把前者连同它的接口、预算与失效边界做实。

::: my-take
我认为「可编辑世界」的真正难点不在编辑操作，而在**编辑之后如何仍然相信这个场景**。渲染图看不出几何错误；而一旦场景被用来生成训练数据或驱动策略，几何错误就会以标签错误或 reward 错误的形式继续往下传，且更难回溯。

所以可信度必须**分级并随数据一起传递**：真实观测、插值视角、生成补全三类样本各报各的指标。把三者混成一句「我们构建了大规模合成数据集」，等于把最不确定的部分藏进了总量里。
:::

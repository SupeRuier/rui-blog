::: tldr
「统一理解与生成」最容易含混的地方，是「统一」没有指定层次。至少可以拆成五层：任务、表示、主干、时空尺度、训练与输出；其中任何一层成立，都不自动推出其他层成立。

Cosmos 3 适合作为案例，因为它把多种能力放进同一个模型叙事里，正好可以逐层检查：哪些是真正的共享，哪些只是接口对齐。

读这类模型时，关键问题不是「能不能同时理解与生成」，而是每一层共享了什么、拆开了什么，以及这种拆分是否必要。
:::

::: question
Cosmos 3 在任务、表示、主干、时空尺度、训练与输出上分别统一了什么？哪些层次只是接口统一，哪些才是真正的共享？
:::

统一多模态模型的讨论容易停在「一个模型既能理解又能生成」。这个说法没有回答一个更关键的问题：统一的单位是什么——任务、表示、参数、时间轴，还是输出接口？

Cosmos 3 提供了一个可以逐层检查的案例。以下按五层框架展开：先拆架构，再看训练与评测，最后回到「统一是否值得」。

## 02 · 分析框架：统一发生在哪几层

把「统一」拆成五层，每层单独判断：

| 层次 | 统一的对象 | 在 Cosmos 3 案例中要回答的问题 |
| --- | --- | --- |
| **任务** | 理解与生成放进同一个模型 | 是同一套权重与接口，还是多个后训练变体？ |
| **表示** | 视觉用离散 token 还是连续特征 | 图像、视频、音频、动作是否共用编码器与 token 空间？ |
| **主干** | 共享 Transformer 还是独立专家 | 参数、注意力、层结构分别共享到什么程度？ |
| **时空尺度** | 图像、视频、长视频的时空结构 | 视频、音频、动作如何对齐时间轴与采样率？ |
| **训练与输出** | 先对齐再混合，还是联合训练 | 损失、训练阶段、输出头是否统一？ |

这五层可以任意组合：统一输出接口不等于统一表示，统一表示也不等于统一训练。对 Cosmos 3 的分析，应该逐层回答「共享了什么、拆开了什么」，而不是给一个总判断。

架构选择还可以沿三组对照轴记录：

1. **离散表示 vs 连续表示。** 离散 token 便于把理解与生成放进同一条自回归序列；连续特征更利于保留感知细节，但生成侧通常需要额外解码路径。
2. **理解的语义需求 vs 生成的细节需求。** 理解偏向抽象语义，生成偏向像素级细节；共享主干时，编码／解码是否必须拆开，是这一轴的核心问题。
3. **共享主干 vs 独立专家。** 共享带来参数效率与跨模态迁移，代价是能力相互牵制；这类代价往往只在混合训练后才暴露。

对 Cosmos 3 的架构拆解，应该能明确回答它在这三组轴上的位置，以及为什么。

## 03 · 架构拆解

这一节按「接入 → token 序列 → 主干 → 输出」展开。重点不是罗列模块，而是标出共享与拆分的位置。

- **模态接入**：文本、图像、视频、音频、动作分别经过什么编码器？哪些编码器冻结、哪些联合训练？
- **统一序列**：不同模态如何排进同一条序列？条件 token 与目标 token 的边界在哪里？
- **共享主干**：参数、注意力、归一化与 FFN 在哪些层共享？哪些路径必须分开？
- **输出接口**：文本、视觉、音频、动作分别如何解码？输出头是否共享？

**待补充。** Cosmos 3 的架构图、token 排列、注意力掩码与输出接口。

## 04 · 训练与数据

训练部分要区分三件事：哪些数据进入预训练、哪些进入后训练，以及统一架构是否改变了配比实验的必要性。

- 预训练、中期训练、后训练分别解决什么问题？
- Reasoner 与 Generator 是否使用同一批数据、同一套损失？
- 初始化来自哪里？哪些能力是继承的，哪些是联合训练得到的？
- 动作与音频数据如何采样、对齐、加权？
- 开放数据与完整训练语料之间差多少？

**待补充。** 训练阶段、数据配比、初始化与消融。

## 05 · 能力与评测

- 理解、生成、动作分别用什么 benchmark？它们是否可比？
- 有没有同算力、同数据的单塔或流水线对照？
- 官方结果与第三方复现之间差什么？
- 物理保真度、任务成功率、动作安全性是否被分别测量？

**待补充。** 评测表、消融与第三方复现。

## 06 · 代价与边界

- **参数与推理成本**：统一主干是否比专用模型组合更贵？
- **数据与训练成本**：统一是否减少了总数据需求，还是只是换了组织方式？
- **架构边界**：哪些模态仍需要专用编码器／解码器？新增模态要改什么？
- **评测边界**：能力覆盖能否证明统一本身带来收益？
- **安全与长时稳定性**：世界模型误差、动作安全、长视频一致性。

**待补充。** 成本数据、失败案例与边界条件。

结论将回到最初的问题：Cosmos 3 的统一发生在哪一层？哪些层次是真正的共享，哪些只是接口对齐？这种统一又付出了什么代价？

::: my-take
判断 Cosmos 3 的「统一」是否成立，更合适的问法不是「它能不能同时理解与生成」，而是「它在哪一层共享、在哪一层拆分，以及这种拆分是否必要」。

统一接口可以降低工程编排成本，但不自动带来表示共享或训练收益。真正值得比较的，是同等算力、数据与后训练预算下的统一骨架与专用流水线；当前公开材料还不足以回答这一点。
:::

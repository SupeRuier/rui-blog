::: tldr
具身数据经常被当成一个「越多越好」的问题，但真正决定能力的是**哪一类数据支撑哪一种能力**。本文把数据来源按「监督密度」与「覆盖广度」排开，并追问三个问题：每层数据各自支撑什么能力、什么时候该加哪一层、以及从「发现缺口」到「拿到数据」要多久。

两个核心判断：

- **金字塔是能力互补关系，不是质量从差到好的排序。** 塔尖监督最密但覆盖最窄，塔底覆盖最广但不含可执行动作；两者不可替代。
- **最被低估的变量是反馈速度**，而不是质量。质量决定单次迭代的上限，反馈速度决定迭代能做多少次，而迭代次数往往更决定最终能力。

本文只讨论数据来源与反馈循环。样本选择算法见主动学习一文，调度层评测与失败归因见《Robot Agent 评测》一文。
:::

::: question
预训练、示教、仿真与真机 rollout、失败轨迹分别支撑什么能力？质量、成本、覆盖度与反馈速度之间怎么权衡？
:::

具身训练需要同时学习感知、物理交互和可执行动作。[Data Pyramid for Embodied Manipulation](https://arxiv.org/html/2607.24744v1) 把数据按**机器人对齐程度**与**采集可扩展性**组织成五层；越接近塔尖，监督越贴近实际机器人，但采集与重置成本也通常越高[@1]。与这条分层并行的一个公开判断是：数据规模已成为世界—动作模型的主要瓶颈，采集效率与规模化能力的权重正在上升[@4]。

## 五层数据来源：由塔尖到塔底

1. **Real-Robot：**真机遥操作、示教与执行轨迹，记录观测、机器人状态、动作及物理后果；动作可在对应硬件上执行，是闭环能力最直接的监督[@1]。
2. **UMI-style：**便携、无机器人参与的人类操控演示，能记录末端执行器和夹爪轨迹；规模更易扩张，但需要标定、重定向和跨本体动作对齐[@1]。
3. **Egocentric / Exocentric：**第一或第三视角的人类活动与操作视频，覆盖手—物交互和长时任务；视角、手部动作与机器人控制接口之间仍有鸿沟[@1]。
4. **Simulation：**仿真交互可并行生成动作、成功信号、接触与位姿等特权监督；需检验视觉、运动学和接触动力学的 sim-to-real 差异[@1]。
5. **General：**大规模图文、视频和通用多模态数据，提供语义、场景和常识覆盖，但通常不包含直接可执行的机器人动作[@1]。

## 每一层支撑什么能力

把五层摊成一张**来源 × 能力**的表，比只画金字塔更有用——它能让「该加哪一层」这个问题有依据：

| 数据来源 | 主要支撑的能力 | 监督形式 | 主要缺口 |
| --- | --- | --- | --- |
| Real-Robot | 闭环动作、接触丰富的操作、失败恢复 | 动作 + 物理后果 | 采集慢、重置成本高、场景窄 |
| UMI-style | 末端执行器轨迹、跨本体动作对齐 | 末端轨迹 | 需标定与重定向；无接触力信息 |
| 第一 / 第三人称视频 | 长时任务结构、手物交互语义 | 视频 + 动作启发 | 与机器人控制接口之间存在鸿沟 |
| Simulation | 特权监督（接触、位姿、成功信号）、大规模并行 | 全状态可读 | sim-to-real 的视觉与动力学差异 |
| General | 语义、场景、常识、语言接地 | 图文 / 视频 | 不含可执行动作，无法直接闭环 |

关键读法是：**这张表不是「从差到好」的排序，而是「监督密度 vs 覆盖广度」的排序**。塔尖监督最密但覆盖最窄，塔底覆盖最广却不含动作——所以它们之间是互补关系，不存在「用某一层替换另一层」的选项。混层训练的意义也在这里：不同层补的是不同的能力缺口，而不只是不同的数据量。

塔尖这一层的可扩展性正被两类努力推动：把采集做成带安全约束的大规模并行系统[@2]，以及按「最大规模 + 最大多样性」组织真实物理数据集[@3]。

## 数据工程的两条主线

**如何生产：**对每层记录任务、视角、传感器、动作坐标系、成功 / 失败及采集成本；比较质量、多样性、复用性和物理真实性。**如何使用：**对齐异构动作和观察，分阶段混合通用数据、仿真数据与真机数据，最终用真实任务评测检验数据配方，而非假设加入更多层就一定更好。失败与恢复、触觉监督和跨本体迁移是值得单独追踪的缺口。

真机自主 Rollout 并非综述的第六层：它属于 Real-Robot 数据中的在线 / 自主采集方式，可为迭代中的当前 Policy 补充失败和恢复轨迹。

## 四个轴的权衡：质量、成本、覆盖度、反馈速度

数据配方本质上是在四个轴之间做显式取舍，四者无法同时最优：

- **质量**：标签是否正确、是否与观测严格一致。合成数据要额外区分真实观测与生成补全。
- **成本**：采集成本、**重置成本**、标注成本、存储与算力成本。真机数据里重置成本最容易被低估——每次采集后把场景恢复原状的开销，经常比采集本身更高。
- **覆盖度**：任务、物体、场景、本体、光照、视角的分布广度。总量达标不代表覆盖齐全。
- **反馈速度**：从「发现缺某类数据」到「真正拿到它」的时间。

**反馈速度经常是最被低估的一个**，因为它不出现在任何成本表里。但它决定的是迭代周期：一次采集要两周，那么策略迭代周期就是两周，再高的数据质量也换不回被拉长的循环。与之相对，真机自主采集的反馈速度最快（缺口出现即可再次采集），代价是分布漂移与安全约束。

因此「加哪一层数据」的正确问法不是「哪一层质量最高」，而是**当前瓶颈在哪一个轴上**：如果是覆盖不足，加塔底；如果是闭环动作不达标，只能加塔尖；如果是迭代太慢，要优化的是采集与重置流程，而不是数据量。

## 反馈循环：数据不是一次采集完的

把数据当成静态资产，是这套体系最常见的误用。实际循环是：

**训练 → 部署 → 失败 → 识别缺口 → 定向采集 → 回到训练**

这个循环里最关键的一环是**缺口识别的分辨率**：如果不清楚失败发生在哪一类场景、哪一层能力上，采集就是盲目的，投入会均匀地摊到所有方向上。而分辨率依赖于执行轨迹记录与失败归因——这也是本文与评测那一篇的交界处。

真机自主 rollout 的独特价值正在于此：它产生的失败分布是**当前策略的真实分布**，而不是人类示教分布。人类示教里几乎不出现失败，所以靠示教数据无法覆盖策略真正会遇到的困难。大规模真机自主采集的公开实践也已经把安全约束作为采集系统的一部分来设计[@2]。但如果目标只是「积累更多真机数据」，而不解决缺口识别，循环依然转不起来。

## 失败与恢复轨迹：最稀缺的一类监督

失败轨迹的稀缺有三个结构性原因：

1. **人类示教几乎不含失败**——没有人会刻意演示失败的抓取；
2. **失败本身是长尾事件**——成功路径收敛，失败方式发散；
3. **恢复要求完整链条**——只记录「失败了」没有价值，需要「尝试 → 失败 → 诊断 → 修正」的连续记录。

而部署中策略遇到最多的恰是这些情形。自主采集与自我改进这条路线，实质上是把失败轨迹转成能力的主要机制：让系统自己产生失败、自己筛选、再回到训练[@5][@6]。这也解释了为什么自主采集值得投入——它不一定产出最干净的样本，但它产出**最相关的**样本。

::: my-take
我认为数据体系里最被低估的变量不是质量，而是**反馈速度**——从发现「缺哪类数据」到真正拿到它的时间。质量决定一次迭代的上限，反馈速度决定迭代能做多少次；而迭代次数往往比单次质量更决定最终能力。

这也解释了真机自主 rollout 为什么值得投入：它未必产出最干净的数据，但它产出的失败分布正是当前策略的真实分布，缺口识别的分辨率最高。反过来说，一个采集周期很长的数据体系，即使单批数据质量很高，也会因为迭代次数太少而落后。
:::
